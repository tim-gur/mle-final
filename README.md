# Цели и использованные технологии
Данный проект решает задачу создания рекомендательной системы товаров для магазина. Целевым действием в рамках проекта является добавление в корзину.  
В качестве структуры рекомендательной системы было решено выбрать двухстадийный подход с дополнительными признаками.  
В данном случае использовалась коллаборативные рекомендации ALS, дополнительные признаки и ансамблирование финальных рекомендаций с помощью catboostclassifier.  

Для увеличения целевой бизнес-метрики конверсии добавления в корзину используется увеличение метрик Precision@10, Recall@10, NDCG@10 рекомендаций модели catboost по сравнению с top10 самых популярных товаров и рекомендаций ALS модели. 

# Архитектура рекомендательной системы:  
- Коллаборативные рекомендации ALS
- Дополнительные признаки
- Модель catboostclassifier, ранжируящая рекомендации

# Архитектура сервиса получения рекомендаций
Рекомендации выдается трем видам пользователей:
1. **Пользователи, для которых не были сформированы персональные рекомендации, и у которых нет истории активности**. Таким пользователям рекомендуются предметы из топ списка.
2. **Пользователи, у которых есть персональные рекомендации, но нет текущей истории активности**. Таким пользователям выдаются заранее сформированные персональные рекомендации.
3. **Пользователи, у которых есть персональные рекомендации, и есть текущая истории активности**. Таким пользователям выдаются смешанные заранее сформированные персональные рекомендации и похожие объекты на объекты из недавней истории. Смешивание происходит по четному-нечетному принципу.

# Описание основных файлов
- EDA: eda.ipynb
- Эксперименты по созданию модели: model_exp.ipynb
- Пайплайн обработки данных и обучения модели: pipeline.py. 

- Шаги обработки данных и обучения модели: scripts/
1. **process_data.py** : обработка изначальных датафреЙмов, изменение формата даты, подсчет топ 100 айтемов и разделение данных на events_train, events_test и events_upd.
2. **als_recommendations.py**: построение модели als на основе матрицы юзеров и весов их просмотров и добавлений в корзину.  
Добавлению в корзину назначается вес 1.0, просмотру - 0.3.
Далее создаются рекомендации для всех пользователей на основе созданной модели.
3. **candidates.py**: создание кандидатов для обучения и теста. Проставление target == 1 событиям со значением addtocart.  
В кандидатах остаются только пользователи с минимум 1 положительным действием. Также для каждого положительного действия остается только 4 отрицательных.
4. **features.py**: создание дополнительных категорий для обучения модели:
- общее кол-во интеракций у юзера
- общее кол-во интеракций у айтема
- общее кол-во просмотров у юзера
- общее кол-во покупок у юзера
- общее кол-во просмотров у айтема
- общее кол-во покупок у айтема
- парный признак просмотров юзеров-айтемов
- подкатегория айтема
- общая категория айтема
5. **fit.py**: обучение модели, получение предсказаний и финальных рекомендаций на основе ранжирующей модели.
6. **evaluate.py**: оценка рекомендаций с помощью метрик, логирование метрик и модели в mlflow.  

- Сервис получения рекомендаций: fastapi_service/
1. **events_service/**: сохранение и получение последних интеракций.
2. **features_service/**: возвращение похожив объектов.
3. **recommendations_offline/**: возвращение персональных рекомендаций или топ объектов.
4. **recommendations_online/**: возвращение похожих объектов на основе недавней истории.
5. **recommendations/**: главный эндпоинт получения рекомендаций.  

- DAG повторного обучения: airflow/dags/pipeline_retrain.py

# Ход работы над моделью
- Контентная матрица по схожести категорий на данный момент не выдает слишком точные результаты (потому что в датасете у большинства пользователей очень мало интеракций) и требует слишком много ресурсов для построения. Пока от нее было решено отказаться.  
- 1 версия: метрики модели низкие, ниже топ и als рекомендаций. Но при этом feature importance показывает ожидаемые данные.
- 2 версия: добавлен парный признак просмотров юзеров-айтемов, метрики значительно увеличились. Он имеет высокий процент feature importance: 50.
- 3 версия: добавлен признак общей категории. Он незначительно повлиял на метрики и имеет низкий процент feature importance.
- 4 версия: совмещение парного признака и общей категории, также изменение методологии измерения метрик (изначально тестовый датасет делился поровну для построения таргета и теста. Из-за этого показатели cb модели были значительно занижены по сравнению с топ10 и als. Однако в этом не было необходимости, поэтому весь датасет был использован для теста, и это значительно увеличило показатели).   
- 5 версия: исправление бага в метриках. Для тестовых событий отправлялся полный датафрейм со всеми типами событий. После исправления отправляются только события addtocart в соответствие с изначальным заданием.
- Финальная версия: добавление дополнительных данных, оставленных изначально для повторного обучения.
